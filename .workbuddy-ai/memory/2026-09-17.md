## Follow-up: the (7%) also appears on the payout-statement PDF

(`generateInvoicePDF`), selected by `invoiceViewer === 'manager'` → title

Payout statement layout, for reference:
- "Chef paid" receipt block: Subtotal, HST (%), Service fee → **Chef paid** = subtotal + HST + fee
- Manager block: Service fee (−), Processing fee (−) → **Net payout** (Stripe-sourced)

**Two pre-existing arithmetic smells in that PDF — NOT changed, needs the user's call:**
1. The manager block renders `Service fee  -$0.70` as a deduction, but the fee is
   chef-paid and `platformFeeWithheldFromManager` is never passed (no `chargeAmountCents`),
   so it is really a bridge step from "Chef paid" back to manager gross — the label reads
   like a charge to the manager.
2. The rows don't reach the printed net: 12.20 − 0.70 − 0.85 = 10.65, but the statement
   shows 10.85 (= 11.50 − 0.65). `stripeNetPayout` comes from Stripe `managerRevenueCents`,
   so either the displayed processing fee or that stored value is off. Needs real
   transaction data to resolve — do not "fix" the math blind.

### PDF inspection trick
`Read` cannot display a generated PDF. Convert for eyeballing with
`sips -s format png <in.pdf> --out <out.png>` (works out of the box on macOS), then `Read`
the PNG. `pdftoppm` is not installed. When importing `pdfkit` from a script outside the
repo, ESM ignores `NODE_PATH` — use the absolute path
`.../node_modules/pdfkit/js/pdfkit.js`.
