# LocalCooksCommunity — project notes

## Tooling & workflow (read first)
- **Never run `tsc` / `npm run build`** (build = `tsc -b && vite build`) — user forbade it. Syntax/import check with esbuild; **`--bundle` is required** or bad `@/` imports pass silently:
  `./node_modules/.bin/esbuild <files> --bundle --packages=external --alias:@=./client/src --alias:@shared=./shared --alias:@assets=./attached_assets --loader:.tsx=tsx --loader:.ts=ts --jsx=automatic '--external:*.css' --outdir=/tmp/x` (quote the glob; `import.meta` warnings under iife are noise). **Type errors are therefore NOT caught** — hand-review refs/generics/type-only imports and say plainly that `tsc` wasn't run.
- **The Edit tool silently no-ops under lock races** (EBUSY / IDE has the file open) while reporting success — always re-read or grep the anchor back after editing.
- `npx vitest run` (~2 min): baseline **8 failed / 1352 passed, all pre-existing**. 13 `client/src/lib/*.test.ts` are script-style (log "ok" and exit → "No test suite found"); `SellerApplication.test.tsx` fails 7 (imports only `chef.json`); `BookingRulesSettings.test.tsx` fails 1 (`getByLabelText("cancellationWindow")` matches both the `<Label>` and the help button `aria-label`). Attribute a failure by copying **just** the suspect file aside → `git checkout HEAD -- <file>` → run → copy back. Never `git stash`. Don't run `tsc` and vitest together.
- Worktree is usually **dirty** — `git status` first. `npx <tool>` rewrites `package-lock.json`; revert if unintended. `npx eslint` fails environment-wide (`zod-validation-error` has no `./v4`) — pre-existing. `npm run dev` may fail `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` after a lockfile change → `mv node_modules/.vite node_modules/.vite.stale-<ts>`. Dev port **5001**.
- **Verify against the published app, never the local dev server.** Auth-gated manager/chef pages **cannot** be verified locally — say so plainly rather than claiming it works.
- Two tsconfigs: `tsconfig.json` (noEmit, client+server+shared) and `tsconfig.server.json` (outDir `dist`, does **not** exclude `*.test.ts`). `rm -f node_modules/typescript/tsbuildinfo` before any typecheck (`incremental` + stale tsBuildInfoFile hides errors).
- DB is **Supabase** (`aws-1-ca-central-1.pooler.supabase.com:6543`) via `DATABASE_URL`. **No Supabase MCP** — for schema/FK questions run a throwaway Node script with `dotenv` + `pg`, read-only `information_schema`/`pg_constraint`, then delete it. The Drizzle schema is **not authoritative** (`kitchen_bookings` predates `migrations/`). **Migrations are NOT applied automatically** — adding `migrations/*.sql` changes nothing at runtime.
- `graphify-out/` = knowledge graph; **`graphify` is not on PATH**; ponytail/archify are `.cursor/rules` personas. Deployment: **Vercel** (`vercel.json`, `vercel-build.mjs`) — `localcooks.ca` + `chef.`/`kitchen.`/`admin.`/`dev-*`, all live. Firebase Hosting site `formauth-9e620` is not the app.

## Design tokens (`client/src/index.css`)
- Brand red `--primary` / `--sidebar-primary` = `hsl(348 85% 59%)`.
- **`--accent` is pure white, same as `--popover`** → `hover:bg-accent` is invisible; use `hover:bg-muted`.
- **`Button` globally applies `chefPrimaryCtaClass`/`chefOutlineCtaClass`** (`lib/chef-cta.ts`) to `default`/`outline`: pill + layered shadow + red glow + `hover:-translate-y-0.5`. `button.tsx` renders `cn(buttonVariants(...), ctaClass, className)` — `className` is last, so it can cancel the CTA (`rounded-lg shadow-none hover:shadow-none hover:translate-y-0`). In dashboard chrome prefer `variant="ghost"` + `hover:bg-muted`.
- **`index.css:698` forces `min-height/min-width: 44px` on EVERY `<button>`** and is emitted **unlayered** in the built CSS (`button:not([data-radix-collection-item])…{min-height:44px}`, verified in `dist/client/assets/index-*.css`) — so an inline icon button in a `text-sm` row renders 44px tall and blows up the row. Specificity (0,3,1) beats a plain utility and there is **no `@layer` wrapper**, so `min-h-0` will NOT win. Reset with `!min-h-0 !min-w-0` (Tailwind **v3** = `!` **prefix**) — **empirically verified**: a scratch Tailwind build emits `min-height: 0px !important`, and `!important` beats the unlayered non-important rule regardless of specificity. **`dialog.tsx`'s close button still has this bug.** (No inline `minHeight` resets exist in the repo — `switch.tsx` does not use one.)
- **Never use `components/ui/field.tsx`** — Tailwind v4 syntax, project is v3.4.17, inert.
- Manager icons: `components/ui/manager-icons.tsx` wraps `@iconify/react`; **only `mdi` is bundled** (other collections need a network fetch that fails here). Brand marks from `react-icons/si` (bundled) — Stripe = `SiStripe`; NOT `client/public/stripe-logo.png` (wordmark). `vite.config.ts` root is `client/` → `client/public/*` serves at site root; repo-root `public/` is NOT the publicDir.

## Identity & verification (email is the primary identifier)
- **`users` has no `email` column** — `users.username` **is** the confirmed email (NOT NULL UNIQUE). `GET /api/user/profile` returns `email`, `emailVerified`, `emailVerifiedAt`, `pendingEmail`, `pendingEmailSentAt`, `pendingEmailExpiresAt`, `resendAvailableInSeconds` (`server/email-verification.ts`). Don't guess from `username`.
- **Gate is email-only**: `requiresEmailVerification()` (client) / `hasVerifiedEmailClaim(req)` (server). Missing phone never blocks; admins exempt. Codes `EMAIL_VERIFICATION_REQUIRED` (apply/tour also `EMAIL_NOT_VERIFIED`). `hasVerifiedEmail` needs **both** Firebase `emailVerified` **and** DB `is_verified`.
- **Branded verification links are server-owned**: `POST /api/user/email/verification/start` → `/email-verify?token=…` → `POST …/confirm`. Only a SHA-256 digest is stored; the address is replaced only **after** the new one is proven (in-flight = `verified-changing`). State machine `client/src/lib/email-verification-state.ts`. Deep link `?view=profile&focus=email` (+`&tab=account` for managers).
- **Firebase caches `email_verified` in the ID token up to an hour** — `reload()` + `getIdToken(true)` first (`fetchEmailVerificationStatus()` does this).
- Auth: only three methods (email verification, Google, phone OTP); no user-chosen password at signup. Email path uses `adminAuth.createUser({...})` with a placeholder password, then `accounts:signInWithPassword` — its `signInProvider` is **`"password"`, NOT `"emailLink"`**. `POST /api/user/sync-password` (`server/routes/user.ts` ~176) mirrors a chosen password into Neon (non-blocking).
- Password tab: `components/auth/ChangePassword.tsx` + `password-form-mode.ts` → `resolvePasswordFormMode()` → `loading | change | set-link | set-update`, rendered in `ChefProfileSettings`, `ManagerProfile`, `ManagerProfileSettings`, `Admin`. **Known bug:** only special-cases `signInProvider === "emailLink"`, so email-verification/phone users wrongly get `change`. `ManagerChangePassword.tsx` is separate, not wired to the helper.

## My Kitchens page (`manager/settings/KitchensManagement.tsx`)
- Tab order **Details & Pricing → Photos → Storage → Equipment**; keep `TabsTrigger` and `TabsContent` source order in sync.
- Kitchen switcher = `DropdownMenu` in the page header whenever ≥1 kitchen exists; it is the **only** place a lone kitchen's name appears and owns "Add kitchen". **`modal={false}` is required** — Radix menus are modal by default and set `disableOutsideScroll: true`, so `<body>` gets `overflow: hidden` and the page scrollbar vanishes while open. Non-modal keeps dismissal/Escape/keyboard nav.
- Tabs are an **underline bar, not a segmented control** (`TAB_TRIGGER`/`TAB_ICON` override the shared `Tabs` primitive). Padding must stay **symmetric** — tailwind-merge only lets a later `py-*` cancel the primitive's `py-1.5`, so `pb-3 pt-1` leaves both rules live and CSS source order wins. Always check `cn(base, override)`.
- Add-kitchen dialog: `CurrencyInput` for the rate, `DialogFooter` cancel-then-create, submit gated on `newKitchenIncomplete` (parsed rate > 0) — testing the raw string lets `"abc"` through to a server 400.
- **Details & Pricing tab lives in `settings/KitchenDetailsPricing.tsx`** (forwardRef, `saveAllChanges`, reports dirty up). Three cards: Details (name + description + smart lock), Pricing, Danger zone. `KitchenPricingContent` is restyled to the row pattern and rendered *by that child*.
- **Save model: one page-level Save** in `ChefPageHeader`, rendered only while dirty (`showSaveAction = kitchensDirty || saveAction.status !== "idle"`). The smart-lock `Switch` saves on change (booleans don't batch).
- `KitchensManagement` takes `saveRef` (plain `Ref<KitchensHandle>` prop + `useImperativeHandle`) instead of `forwardRef`, to avoid a 630-line re-indent of a file that suffers silent-edit failures. Shell wiring mirrors Booking Policies: `kitchensSaveRef` / `bypassKitchensGuard` / `kitchensDirty` / `pendingKitchensView`.
- **Tab and kitchen switches are guarded** — Radix unmounts inactive `TabsContent`, destroying form state. Dirty is masked as `activeSection === DEFAULT_KITCHEN_SECTION && detailsDirty`.
- Currency is **CAD only** (`CURRENCY` in `KitchenPricingManagement.tsx`); the CAD/USD/EUR `Select` is gone.

## Kitchen data model & delete
- **`kitchen_bookings.kitchen_id` is the ONLY FK to `kitchens` that is `ON DELETE NO ACTION`**; all 11 siblings cascade. A plain `DELETE FROM kitchens` **aborts for any kitchen ever booked** → 500. `KitchenRepository.delete` now deletes `kitchenBookings` then the kitchen inside a `db.transaction` — one choke point fixing both the manager route and `server/routes/admin.ts:1857`.
- Deleting bookings cascades to `access_code_audit`/`storage_bookings`/`equipment_bookings` (and children). `damage_claims` is `SET NULL` for both booking FKs, so claims survive delinked.
- **Two different "minimum" settings — do not merge:** `kitchens.minimum_booking_hours` = per-kitchen booking *duration* (`PUT /kitchens/:id/pricing`); `locations.minimum_booking_window_hours` = per-location advance-notice *window* (`PUT /locations/:id/cancellation-policy`). Server cross-validates a kitchen's minimum duration cannot exceed the location's `defaultDailyBookingLimit`.
- `GET /manager/kitchens/:kitchenId/delete-impact` → `{ bookings: n }` drives the delete dialog. Two segments after `/kitchens`, so no conflict with `GET /kitchens/:locationId`. `putKitchenDetails` accepts and now validates `name` (non-empty after trim, ≤120 chars).

## Shared UI conventions
- `settings/SettingsRow.tsx` exports `SettingsRow` + `RowHelp` (ⓘ popover). `layout` = `inline` (label left, control right) or `stacked`. Use it for new settings rows instead of hand-rolled `divide-y` rows.
- Layout: `ChefPageHeader` + cards + `StatusButton`. `StatusButton` **swallows thrown errors** — re-throw after toasting. `useStatusButton(fn)` shows success when `fn` resolves, so a saver returning `false` instead of throwing falsely shows success. One label per setting (no group title + field label).
- Contact info: `components/profile/ContactVerificationRow.tsx` exports `ContactInfoCard` (divided list), `ContactVerificationRow`, `ContactStatusPill`, type `ContactTone` (`verified|action|pending|empty`). **Email and phone are always siblings in one `ContactInfoCard`**, never in the profile field grid; editing expands inline, row shape never changes. **Three-line structure is fixed**: `value` → `secondary` (one-line status) → `description`; no state may omit `secondary`. Verified icon is the **same on both rows**: `Check` from lucide (not `CheckCircle2` for phone); `Mail`/`Phone` only for unverified/empty, `Clock` for pending. Three hosts must stay in sync: `ChefProfileSettings.tsx`, `ManagerProfileSettings.tsx`, `pages/ManagerProfile.tsx` (legacy, live at `/manager/profile`). `Section` in `ChefProfileSettings.tsx` has `flush` (no body padding + `overflow-hidden`).
- Greetings: name always `user.displayName` (legacy `fullName` unused). "Now" = device local time, no timer. Boundaries duplicated in **two** places — `KitchenDashboardOverview.tsx` (`goodMorning`, manager ns) and `chef/dashboard/OverviewTabContent.tsx` (`ovGood*`, chef ns); update both (grep `getHours()`).
- Dead code: `SettingsView` (~1549 in `ManagerBookingDashboard.tsx`) and `LocationSettingsView.tsx` hold booking-rules UI **never rendered**. `chef/ChefOverview.tsx` never rendered (its `overview*` keys duplicate `chef.json`/`kitchen.json`; live greeting is `chef/dashboard/OverviewTabContent.tsx`). `KitchenPricingManagement.tsx`'s **default export** is imported nowhere — only the named `KitchenPricingContent` is used.

## Money & PDFs — two generators, don't confuse them
- **The booking-details "Download payout statement" button uses `server/services/invoice-service.ts`** (`generateInvoicePDF`, chosen by `invoiceViewer === 'manager'` → title key `payoutStatementTitle`). `server/services/payout-statement-service.ts` is a **different, older** generator (Statement #/Payout ID/Period/Summary) whose PDF has **no service-fee line at all** — editing it changes nothing the manager sees. `invoice-service.ts` also handles the chef invoice (`else` branch) and the standalone storage-extension invoice.
- Service fee is **chef-paid** (`shared/booking-pricing-breakdown.ts` money model): `chefTotal = kitchenSubtotal + kitchenHst + platformFee`, `kitchenNetPayout = kitchenGross − processorFee`. `platformFeeWithheldFromManager` is only true when `chargeAmountCents` ≈ gross — pass it, or the flag silently reads false.
- Manager-facing service-fee copy lives in the **`chef` i18n namespace** (the manager view of `BookingDetailsPage` uses `useTranslation("chef")`). Key `bdLocalCooksFeePaidByChef` = "Service fee · paid by chef" (no rate); `bdServiceFeeInfo{Aria,Title,Body}` drive the ⓘ popover. Chef-facing receipt keeps the rate.
