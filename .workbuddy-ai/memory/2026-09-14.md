# 2026-09-14

## Manager sidebar "Getting started" popover rework

Reworked `client/src/components/manager/ManagerGettingStarted.tsx` (the sidebar flyout):

- Rows are now the controls — removed the "Continue Setup" / "Complete listing" CTA `<Button>`.
- Completed rows are **read-only** (plain `<div>`, no hover, not navigable); only open steps + listing improvements are `<button>`s.
- Added per-step Iconify icons at the right end of each row, reusing the icons the onboarding flow already uses (CompletionSummaryStep / EnterpriseStepper).
- Payments uses the Stripe **"S" mark**: `import { SiStripe } from "react-icons/si"` with `iconClassName: "size-3.5 text-stripe"` — matching the existing convention on the chef dashboard overview (`chef/dashboard/OverviewTabContent.tsx`). Two earlier attempts were wrong: `simple-icons:stripe` via Iconify never rendered (collection not bundled), and `client/public/stripe-logo.png` is the full **wordmark**, not the initial.
- Checkbox rule: complete = brand-coloured `Check`, incomplete = empty `Circle` outline (removed the emerald `CheckCircle2` and the filled `bg-primary` dot).
- Fixed row alignment: marker is now `top-1/2 -translate-y-1/2` so the tick lines up with the row text regardless of padding.
- Fixed invisible hover: `hover:bg-accent` renders as nothing because `--accent` is `0 0% 100%` — identical to `--popover`. Switched to `hover:bg-muted`.
- Added 6 short action-phrase i18n keys (`managerSetupStep*`) to en-CA / fr-CA / uk `manager.json`.

Wiring: `app-sidebar.tsx` gained `SETUP_STEP_VIEWS` (step id → manager view) and deep-links rows through the existing `onViewChange` → `handleViewChange`, so the availability-unsaved guard still applies. Removed the now-dead `onContinueManagerSetup` prop from `app-sidebar.tsx`, `DashboardLayout.tsx`, `ManagerBookingDashboard.tsx` (the `handleContinueSetup` handler stays — `OnboardingStatusBanner` still uses it).

## Unrelated bug found + fixed

`gettingStartedProgress` in all three `chef.json` locales used double braces (`{{completed}} of {{total}} complete`), which i18next-icu renders literally and `client/src/i18n/locales.test.ts` rejects. Also fixed the same double-brace `defaultValue` in `client/src/components/auth/ProfileGettingStarted.tsx`. This was breaking 3 tests before the change.
