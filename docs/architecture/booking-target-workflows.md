# Proposed Inngest and communication design

2026-10-11. All target behavior J, pending owner approval. [Consolidated architecture](booking-target-architecture.md); [current inventory, scheduler/retry evidence and source indexes](booking-communications.md). Communication timing in current code is R, not approved product policy; current diagnostics are mocked T, not provider/time guarantees.

## Keep orchestration small

**R:** `server/lifecycle-inngest.ts` has two source functions: `lifecycleTick` (enabled matching-environment two-minute cron or rehearsal event, concurrency 1, retries 1) and `startingChatEmail` (chat event, 15-second sleep, retries 3, per-conversation concurrency 1). `functions/src/chat-trigger.ts` and `chat-email-event.ts` persist SQL intent before publishing chat events. No booking `sleepUntil`/`waitForEvent` was found. `recurring-worker.ts` uses fair checkpoints, bounded batches and a dedicated session-capable connection; local Supabase transaction pooler is not suitable for its session advisory lock. Generated/deployed code agreement and actual activation remain Q.

**Recommendation:** retain the bounded SQL due-work sweep as primary deadline/recovery mechanism. Add booking operation/settlement tasks to the existing fair worker, not a new workflow function for every email. Domain commits persist outboxes and due-time intent; Inngest wakes processing. Optional identity-only event wakeups improve latency but are not required for truth. An event publication failure leaves work discoverable in SQL. Two-minute cadence is not a guaranteed delivery SLA. Dedicated session connection, signed callbacks and environment routing are mandatory deployment gates.

Persist `dueAt`, `expiresAt`, timezone, booking/policy/schedule revision and semantic event identity. Compute eligibility on commands and sweeps with server time, not only on cron. Rescheduling invalidates obsolete due intents and creates a new revision. UTC determines ordering; kitchen IANA zone determines disclosed local deadlines. Avoid global `America/St_Johns` assumptions and fixed UTC offsets; test Newfoundland half-hour offset, DST gaps/folds and overnight operating dates. Store the selected instant/offset for ambiguous time choices; reject or explicitly resolve nonexistent local times.

## One delivery contract across existing families

Reuse B booking, T tour, A advance, O outcome and C chat records, with a common attempt contract rather than a generic rules engine:

1. Commit domain event and intended recipient roles with business state. Payload includes identities/revisions, not permanent permission to send old content.
2. Claim due intent with row lease and stable recipient-specific semantic key. Partition ordering by booking/case, not globally. Different channels have independent outcomes.
3. Immediately re-read booking/payment/refund/case/terms, deadline validity, recipient identity/role/assignment, preferences and permission to see content. Generate minimal text from current authoritative state. Late historical facts may be delivered as facts; stale action buttons/ICS/instructions are suppressed.
4. Record attempt before provider IO. Stable key example: `booking:<id>:<semantic-event>:<revision>:<recipient-id>:email`. Financial messages include operation ID. Chat uses conversation/message/episode identity. A retry does not create a new semantic revision.
5. Transient failure retries with bounded backoff/jitter and next attempt before usefulness expires. Permanent invalid address/permission marks failed/suppressed, creates operator task where critical. In-app task survives email failure.
6. SMTP accepted is transport acceptance, not proof of inbox delivery/read. Timeout after possibly accepted send becomes **uncertain**, pauses blind retries and exposes manual/provider verification. Adopt tour attempt/uncertainty discipline for booking/outcome/advance families. Exactly-once SMTP is not promised; include visible event identity so unavoidable duplicate mail is recognizable.

Before email send, role/recipient changes suppress sensitive material; the former manager should not receive a reminder simply because an outbox captured an old address. History preserves attempted recipient securely. Actual email envelope/sender/reply-to must be verified independently of recipient. Test sender identity does not make arbitrary development users approved test recipients. In-app notifications require the same current authorization.

## Event, email and timing matrix

All offsets and deadlines below use approved saved policy, not unapproved new constants. C/M/A mean customer/manager/admin. Until limited staff scopes exist, only the owner/named authorized administrators operate queues; do not hand support staff full admin. Case-read/messaging and payment-operation permissions are separate. Every row has an in-app timeline/task; critical undelivered/uncertain outcomes appear to A. Existing R coverage is linked in the current communication report; future acceptance tests are in [phase plan](booking-target-phases.md).

No native push/FCM delivery implementation was found in targeted investigation [R]; current in-app bells/sounds are not device push. Defer SMS/native push until need, isolation, consent and approved numbers/tokens are proven. Do not activate Twilio/Firebase delivery because credentials exist. In-app and email suffice for launch if critical tasks have operator recovery.

## Edge-case and failure acceptance matrix

| Scenario | Required behavior | Verification / observability |
|---|---|---|
| DST spring gap/fall overlap, St John's half-hour offset, overnight slots | Resolve actual instant once; show chosen local date/zone; deadline uses saved instant | Fake clock + IANA calculations; golden cases across offset transition |
| Rescheduled/cancelled after timer queued | Re-read state/revision, suppress old reminder; new notice due appropriately | Queue old reminder then commit change/cancel; stale suppression reason count |
| Last-minute booking/missed worker run | Refuse capture after deadline; consolidate timely prep; skip expired tasks | Fake clock before/after exact boundaries; worker late backlog run |
| Provider expires authorization earlier than product SLA | Shorter saved deadline; reconcile cancel; no confirmation | Mock actual capture_before and out-of-order PI events; expired pending age |
| Duplicate event, Inngest replay, concurrent sweeps | Same semantic outbox and operation; one domain effect; delivery attempts traceable | Duplicate IDs/concurrency with transaction fixtures; no double capture/transfer |
| Out-of-order webhooks | Store signed event once, retrieve current object where needed; no older-state regression | Reverse event order including refund/dispute/payout; unapplied/failed inbox age |
| SMTP timeout after acceptance / crash before sent commit | Mark uncertain, pause blind resend, in-app task remains; operator can verify/resend audibly | Accepted-then-timeout mock; attempt history/uncertainty queue |
| Participant loses permission between queue and send | Suppress unauthorized sensitive content; current recipient gets appropriate new task | Reassignment/revocation fixture before IO; permission suppression count |
| Policy changed after booking | Existing schedule/deadline/text unchanged; future booking uses new version | Compare accepted snapshot/email/quote/document across edit |
| Payment finality delayed | No confirmed paid/refunded notice before financial truth; pending task visible | Capture/refund pending and lost reply; money-state/message consistency |
| Workflow destination/signing key wrong | Fail closed; no unauthenticated execution or cross-environment event | Verified isolated config exercise only; environment/account identity telemetry |
| Permanent bounced critical notice | Business decision doesn't wait for delivered email; in-app and operator task | Invalid-address mock; unresolved critical notices queue |

Worker lag must never redefine cancellation eligibility, claim response rights or booking access. A legally/materially important notice missed by the platform may require an admin extension/customer remedy under approved policy; do not silently shorten response time because a delayed email finally arrived. Store business due time and actual transport attempt/delivery observations separately.

The proposed workflow remains at-least-once orchestration with idempotent domain operations and honest delivery uncertainty. Deterministic fake-time tests prove decisions and suppression logic; only isolated staging exercises prove signed routing/worker activation/provider behavior, and neither proves all future production timing.
