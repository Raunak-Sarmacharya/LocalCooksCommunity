## 3. Decisions locked (details in PHASE0_LOG.md Oct14/Oct13)

- **Arrival & departure:** always on (the per-kitchen tracking switch is removed); only customer tasks are optional (once added, they're required).
  - Location default + per-kitchen override for instructions and tasks.
  - Live instructions with an "instructions updated" email (chef-only; departure changes also reach checked-in chefs).
  - Terms are a location-level PDF only (house rules and legal terms), accepted at application, with no checkout checkbox.
  - Access is approved per location.
- **Cancellation policy:** Flexible/Moderate/Strict presets, no custom tiers.
  - Before confirmation: the hold is released 100%.
  - After confirmation, before the window: instant automatic refund minus the actual Stripe fee; the manager can't cut it.
  - Inside the window: per the preset tier, and the manager may refund MORE only.
  - Policy and terms are versioned (edits apply to new bookings only).
  - A notice is shown before paying if the booking falls inside the window.
- **Kitchen cancels after confirmation:** the chef gets 100%; Local Cooks absorbs the rare Stripe fee in the pilot; kitchen cancellations are tracked.
- **Other policy rules:**
  - No-show = cancellation at start.
  - Unusable kitchen = kitchen-cancel rules.
  - Exceptional refunds are Local Cooks-funded.
  - The response deadline is capped before start.
- **Payout:** after session closeout (inspection/claim windows), then Stripe's schedule.
- **Closeout clocks (admin-configurable):** service ends at the scheduled end + 15 min; inspection auto-closes 24 h after the later of scheduled end and departure, as "no inspection recorded".
- **Chef documents:** reminders at 30/7/0 days; new bookings blocked on expiry.
- **Visit code (APPROVED):** staffed code + manager-enabled self check-in (one action for all days of a multi-day booking).
  - An additive table storing a keyed hash, mode, revision, attempts and replay id.
  - A new server secret env var (local first; ask before setting it on Vercel).
  - A 6-digit code, 5 attempts, then the manager rotates it.
  - New confirmations only; it never moves money.
- **In-session screen (ADOPTED):** a live countdown; "Need more time?" → in the last 15 min "Start check-out"; leave early, message the kitchen, report a problem, get help; an alert 15 min before the end; the manager board mirrors it. Build it with the visit code.
- **Invites:** a discount on the kitchen price only (floor $1), default expiry 48 h (24 h–7 d), pre-approved booking, sent only by the location manager, with full support controls.
- **Extension / early / late:** chef "Need more time?" or a manager "Offer more time" → a manager offer for adjacent free time → one-tap pay → a linked booking shown as one longer visit. Reuses invites.
- **Multi-day:** one booking with N daily visits, all or nothing; per-day cancellation cutoffs; per-day check-in, tasks and code (day 2+ compact); default ON for daily-rate kitchens, min 1 / max 7 (max 1 = off); weekly standing bookings OUT.
- **Storage (FINAL):** its own monthly product per unit, with a daily holdover rate.
  - Monthly in advance on the saved card (platform is merchant); the kitchen is paid after the month closes.
  - The manager approves the first rental only; auto-renew.
  - Anniversary billing; cancel anytime (stops renewal); move out early anytime; no partial refunds (owner may override).
  - 5-day payment grace, then access paused and holdover starts; abandoned goods handled manually by support; legacy rows keep their contract.
  - "Manage my storage" plus a manager occupancy view. DB changes only once the build plan is final.
- **Manager Customers area:** design in `design-manager-customers.md`; restricting kitchens per customer is P2 (not now); account-deletion history is handled manually for now.
